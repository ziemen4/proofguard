# Contributing

## Setup

Follow the [quickstart](docs/quickstart.md) to install the pinned toolchain. Then run
the suites your change touches:

```sh
python3 scripts/review-tests.py foundation
python3 scripts/review-tests.py plugin plugins/meijer/tests.json
npm ci --ignore-scripts --prefix integrations/pi
python3 integrations/pi/review.py
```

They use real sandboxes and the real checker; foundation and Meijer take about 20
minutes each on 8 cores. CI runs all of them on every pull request and fails on any
failure or skipped test.

## Structure

ProofGuard has three parts that must stay independent:

- the foundation (`proofguard/`, `bend-spec/`) names no plugin or harness;
- plugins (`plugins/`) never import a harness;
- harnesses (`integrations/`) never import a plugin, and outside their tests and
  `review.py` use only `proofguard.session`.

`tests/core/test_boundaries.py` checks these rules. A plugin or harness keeps its
code, docs and tests in its own directory; a test that needs a specific plugin and
harness together goes in `tests/composition/`. The guides explain how to
[write a plugin](docs/guides/write-a-plugin.md) and
[add a harness](docs/guides/add-a-harness.md).

## Changes

- Add a test that fails without your change, using the real toolchain and sandbox
  rather than mocks where the suite already does.
- Keep the docs true to the code. Pages live in `docs/` and in each plugin's or
  harness's README; `site/pages.mjs` lists them for the docs site, and
  `cd site && npm ci --ignore-scripts && npm run build` checks every link. Diagrams
  are generated by `docs/assets/diagrams.py`.
- Report security problems privately, as described in [SECURITY.md](SECURITY.md).
